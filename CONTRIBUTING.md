# 🤝 Contributing to WHITE STAR SOUVENIR WORKS

Thank you for your interest in contributing to **WHITE STAR SOUVENIR WORKS**!

Contributions from everyone are welcome. Whether you're a developer, designer, Titanic enthusiast, or simply someone with a creative idea, you're welcome to participate.

You don't need to be an expert to make a difference. Every constructive contribution is appreciated.

## How You Can Contribute

There are several ways to help improve this project:

- **Bug Reports:** Identify and report errors, unexpected behaviour, or technical issues.
- **Feature Suggestions:** Propose new features and improvements.
- **Code Contributions:** Submit bug fixes, enhancements, and new functionality.
- **Design Improvements:** Suggest better layouts, templates, typography, and visual elements.
- **Documentation:** Improve instructions, descriptions, and project documentation.
- **Feedback:** Share your experience and suggest ways to improve the project.

## Getting Started

If you want to contribute code, follow these steps.

### 1. Fork the Repository

Fork the repository using GitHub's Fork button.

### 2. Clone Your Fork

```bash
git clone https://github.com/YOUR_USERNAME/titanic-viewcard-generator.git
```

### 3. Navigate to the Project

```bash
cd titanic-viewcard-generator
```

### 4. Create a Branch

Create a separate branch for your contribution.

```bash
git checkout -b feature/your-feature-name
```

For bug fixes, you can use:

```bash
git checkout -b fix/your-bug-fix
```

### 5. Make Your Changes

Implement your improvements while maintaining the project's existing structure and design direction.

### 6. Test Your Changes

Before submitting:

- Check that your changes work as expected.
- Ensure existing functionality is not unnecessarily broken.
- Check the browser console for errors.
- Test relevant layouts and features.

### 7. Commit Your Changes

Use a clear and descriptive commit message.

```bash
git add .
git commit -m "Add: describe your changes"
```

### 8. Push Your Branch

```bash
git push origin feature/your-feature-name
```

### 9. Submit a Pull Request

Open your fork on GitHub and submit a Pull Request to the original repository's `main` branch.

Include a brief explanation of your changes and why they would benefit the project.

## Contribution Guidelines

To maintain consistency and quality, please follow these guidelines:

- Keep the interface clean and user-friendly.
- Preserve the project's vintage maritime and Titanic-inspired visual identity.
- Avoid unnecessary dependencies.
- Write clear and maintainable code.
- Keep changes focused and relevant.
- Test your contributions before submitting them.
- Be respectful and constructive when discussing ideas or reviewing contributions.

## Images, Fonts & Third-Party Assets

Please respect copyright and licensing requirements when contributing external assets.

- Only submit assets you created or have permission to use.
- Include attribution where required.
- Provide the original source and licence information when applicable.
- Do not submit copyrighted images or materials without the necessary permission.
- Clearly identify assets that have separate licensing conditions.

Submitting a contribution does not transfer ownership of third-party materials or grant additional rights to use them.

## Pull Request Guidelines

Before submitting a Pull Request, make sure that:

- The title clearly describes your contribution.
- The description explains what you changed.
- Related issues are referenced where applicable.
- Screenshots are included for significant visual changes.
- Your changes have been tested.
- No unrelated files or changes have been included unnecessarily.

## Reporting Issues & Suggesting Features

You are welcome to open a GitHub Issue if you:

- Find a bug.
- Have an idea for a new feature.
- Notice a design or usability problem.
- Have a question about the project.
- Want to discuss a potential improvement.

Please provide enough information for others to understand your report or suggestion.

## Code of Conduct

All contributors are expected to communicate respectfully and constructively.

- Be welcoming to people of all experience levels.
- Respect different opinions and perspectives.
- Provide constructive feedback.
- Avoid harassment, discrimination, or personal attacks.
- Keep discussions relevant and productive.
